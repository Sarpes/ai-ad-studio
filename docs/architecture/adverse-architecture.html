How AdVerse works

One product photo becomes ads for up to three audiences ("universes"). This page shows the user's path through the app, how the code is organised, and every call that leaves the server.

1 · User flow

From login to a finished video

The name typed at login is the account: it becomes the RevenueCat customer ID. Nothing is charged until the user approves the ideas, and only images that actually come back cost credits.

Safety rules in code

  • Every image and video prompt gets the fixed rule: keep the product exactly as photographed, no text or claims.
  • Free images are watermarked on the server with sharp, so a download keeps the mark.
  • The clean original of a free image stays on the server; after an upgrade the video uses it.

Money rules in code

  • Credits are checked before calling fal and charged only for delivered images.
  • An unverifiable plan counts as Free, unless ALLOW_INSECURE_DEMO=1 (demo laptop only).
  • FAL_MAX_JOBS caps fal jobs per server run (40 for the demo).

fal.ai

  • fal-ai/any-llm · Director ideas · ~$0.001
  • fal-ai/nano-banana/edit · images · $0.0398 each
  • minimax/h3-max/image-to-video · $0.035 / s
  • Key: FAL_KEY, server only

RevenueCat

  • Project "Poof", Test Store app
  • Products: adverse_creator_monthly, adverse_studio_monthly, adverse_topup_10
  • Entitlements creator, studio · offering adverse_tiers · currency CRD
  • Test Store "month" = 5 minutes, renews 5 times

Tunnel (ngrok via Expo)

  • The server runs on the home PC; the phone at the venue reaches it through a public *.exp.direct address.
  • The address changes on every restart.
  • Open only during the demo; stop it afterwards.

Known gaps (see DECISIONS.md): no real user accounts yet; without a RevenueCat secret key the server trusts the app's plan on the demo laptop; live updates do not reach the phone through the tunnel, so reload Expo Go after every change.
